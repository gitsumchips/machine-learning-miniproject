# Vision-Based Pose Estimation Lab

This project is a small, reproducible simulation lab for studying how a camera-equipped aircraft could estimate another aircraft's relative pose during formation flight. It is inspired by Rohan Punnoose's 2020 Stanford paper, *Vision-Based Precision Pose Estimation for Autonomous Formation Flying*.

Rather than using real camera images, the lab creates a simplified aircraft model, projects selected points on that model into a simulated camera, and uses the resulting pixel locations to estimate pose. This makes it possible to experiment with the data-generation assumptions, a neural-network classifier, and a particle filter without needing flight hardware or an image dataset.

> **Scope:** This is an educational simulation and partial reproduction, not flight software. Some geometry, camera, and motion details are simplified or assumed where the paper does not specify them.

## What the lab does

The core experiment has three steps:

1. **Generate synthetic measurements.** Sample relative aircraft poses, render 14 model keypoints through a pinhole camera, and mark points that are occluded or outside the image as undetected. The pose labels discretize position `(x, y, z)` and roll `phi` into 4,800 classes. Pitch and yaw are not part of the classifier label.
2. **Train a pose classifier.** A small multilayer perceptron receives 42 values per sample (horizontal and vertical pixel coordinates plus a detection flag for each of the 14 keypoints) and predicts one of the pose classes.
3. **Refine estimates over a trajectory.** A particle filter uses the ANN's pose estimates and simulated feature measurements to track relative position and attitude as the follower approaches the leader.

The code generates both a random dataset for training and a scripted approach trajectory for the tracking experiment. It reports validation/test metrics and saves plots and intermediate data so you can inspect or rerun individual stages.

## Repository files

| File | Purpose |
| --- | --- |
| `dataset_generation.py` | Aircraft and camera geometry, feature projection and occlusion, pose labels, synthetic dataset and trajectory generation, and shared plotting / file helpers. |
| `train_ann.py` | Defines, trains, evaluates, and saves the ANN pose classifier. |
| `particle_filter_ann.py` | Runs the trajectory-based particle-filter experiment using a trained ANN. |
| `main.py` | Runs selected stages in sequence and creates a comparison report from available results. |
| `ML_miniproj_colab_file_2.ipynb` | Minimal Google Colab notebook that mounts Drive and launches `main.py`; it is optional for local use. |

## Requirements

- Python 3.10 or newer
- NumPy
- Matplotlib
- PyTorch

The core dataset, ANN, and particle-filter stages do not require a downloaded dataset. All measurements and labels are generated by the project.

## Install locally

From a terminal, change to the project directory:

```bash
cd machine-learning-miniproject
```

Create and activate a virtual environment. On macOS or Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

On Windows PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install the dependencies:

```bash
python -m pip install --upgrade pip
python -m pip install numpy matplotlib torch
```

PyTorch's installation instructions may offer a platform-specific command for your machine; use that if the standard `pip install torch` command is not suitable. The training code uses CUDA when available and otherwise runs on CPU.

## Run the experiment

The default dataset contains one million generated samples, which can take a while and use substantial memory. For a first run, use a smaller dataset and fewer training epochs:

```bash
python main.py --stages dataset ann pf --n-samples 50000 --epochs 5 --seed 0
```

The selected stages run in dependency order: dataset generation, ANN training, then particle filtering. The particle-filter stage runs both configured experiments (A and B). Increase the sample count and training epochs for more substantial experiments, for example:

```bash
python main.py --stages dataset ann pf --n-samples 200000 --epochs 40 --seed 0
```

To run or repeat a single stage after its prerequisites have been generated:

```bash
# Generate the dataset and approach trajectory
python dataset_generation.py --out outputs --n-samples 50000 --seed 0

# Train the ANN using the generated dataset
python train_ann.py --out outputs --epochs 5 --seed 0

# Run both particle-filter configurations using the saved ANN
python particle_filter_ann.py --out outputs --seed 0
```

Run commands from the project directory so the scripts can import each other. Keep the same `--out` directory across stages: the ANN needs the generated dataset, and the particle filter needs the generated trajectory, trained model, and ANN validation error distribution.

### Useful options

```bash
python main.py --help
python dataset_generation.py --help
python train_ann.py --help
python particle_filter_ann.py --help
```

`--out` selects where generated data and results are saved. `--seed` makes the random portions of an experiment repeatable. Dataset generation also accepts `--att-jitter-deg` and `--min-range` to vary its simulation assumptions.

## Outputs

By default, generated artifacts are written under `outputs/`:

- `outputs/data/` — compressed synthetic dataset, approach trajectory, and ANN error samples used by the particle filter.
- `outputs/models/` — trained ANN checkpoint.
- `outputs/figures/` — generated trajectory, training, and estimation-error plots.
- `outputs/results/` — dataset statistics, ANN metrics, and particle-filter result arrays.

These files are created when you run the lab and are not required as input beforehand. Use a different `--out` path to keep separate runs side by side.

## Current project limits

The `main.py` driver also lists `xgb` and `ba` stages, but their implementation files (`train_xgboost.py` and `bundle_adjustment_xgb.py`) are not included in this repository. Therefore, do not run `main.py` with its default stage selection: it will reach the unavailable XGBoost stage and fail. The local workflow above selects only the included `dataset`, `ann`, and `pf` stages.

The notebook is Colab-specific: it imports `google.colab` and assumes `main.py` is available in the notebook's current directory. For a local experiment, use the terminal commands above instead.
